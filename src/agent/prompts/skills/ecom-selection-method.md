# 选品方法论（战术手册）

选品是**探索型任务**，不是固定流水线——没有哪两个品类该走同一条路径。本手册是打法；工具清单与输出契约见 agent 角色提示词。

## 平台与语言（核心规则）

两个数据源语言不同，**你负责说对语言**：

| 数据源 | 语言 | 说明 |
|--------|------|------|
| `corpus_overview` / `search_amazon` | **英文** | 语料是亚马逊英文搜索页抓取（28k 商品）。用英文词查：air fryer、rice cooker、pet feeder。中文词查英文语料只会得到诚实的空。 |
| `search_1688` | **中文** | 1688 是国内货源平台（真源接入前该工具如实返回空）。用中文词查：空气炸锅、电饭煲。 |

你自己做翻译——用户说「空气炸锅」，你查 Amazon 用 "air fryer"，查 1688 用「空气炸锅」。**不要把用户的中文原话直接塞给 Amazon 侧工具。**

## 选品 CLI 调度（工具分工）

选品工具分两层，按任务形态选用，不是每次全用：

| 层 | 工具 | 什么时候用 |
|----|------|------------|
| **确定性内核** | `run_selection(用户需求原话)` | 用户要「选品/推荐/找货」这类**完整选品需求**时调用——内部执行检索→匹配→筛选→五维评分，产出结构化报告卡并落库，用户直接看到卡片。调用后你只做一两句点评/追问，不复述报告。 |
| **灵活探测层** | `corpus_overview` / `search_amazon` / `search_1688` / `category_trend` | 单点探测、竞品深挖、换关键词迭代、回答「这个品类有什么」等**非完整选品**诉求——按下面的探索战术自由组合，不产出报告卡。 |

判断标准：用户要的是「一份选品结论」→ run_selection；用户在跟你一起探索市场 → 探测层。两者不互斥：run_selection 内部已含检索评分，**不要先手动检索一遍再调 run_selection 重复算**；探测层的发现可以帮你改写传给 run_selection 的需求描述。

## 探索战术

1. **先探测后深入**：`corpus_overview("air fryer")` 看覆盖——多少款、什么价格带。有数据→继续；没数据→换上位词/近义词再探一次；仍无→如实告知该品类不在语料库，建议换覆盖的品类（见返回的大类概况），**不要带用户空转调参**。
2. **解析意图要忠实**：从用户消息提取关键词、预算（人民币）、偏好。关键词忠实于用户原话；用户没提预算就不要假设。英文检索词由你翻译，不篡改用户的品类意图。
3. **关键词迭代基于分侧结果**：核心词命中薄 → 换上位词（air fryer → kitchen appliance）、形态词（compact air fryer / dual basket air fryer）、配件词（air fryer accessories / air fryer liners）。每轮只动一侧、只改一个变量，上一轮的真实返回决定下一轮方向。
4. **不对称结果如实呈现**：一侧厚一侧薄/空 → 报告里写清楚哪侧有什么、哪侧缺什么。亚马逊侧有真实数据就是有价值的分析素材（价格带、评分分布、头部品牌），**不要因为 1688 侧空就输出一句「0 候选」了事**——用亚马逊侧做市场分析，货源侧如实标注「暂无数据源」。
5. **筛选与评分**：候选多（>6）时先 `hot_filter_candidates` 规则初筛；少则直接评分。评分结果必须来自 `score_candidates` 工具返回，不得自己编造分数。

## 五维评估框架

候选按五维打分（score_candidates 工具执行，权重合计 1.0）：市场需求 0.25 / 竞争度 0.20 / 利润 0.30 / 季节性 0.10 / 复购 0.15。价差比硬门槛 ≥1.5（`PRICE_GAP_RATIO_THRESHOLD`）——低于此值不进评分。

## 预算纪律

- 每次 run 工具调用**总预算 ≤20 次**。探测 1-2 次、检索 2-6 次、评分 1-3 次是常态。
- 收到"预算将尽，立即用现有数据收尾"的提示后，**不得再调用任何工具**，直接用已有数据输出最终报告。
- 不要做无意义的重复调用（同样的关键词查两次、同批候选评两次）。
